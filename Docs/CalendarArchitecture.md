# Calendar 日历模块 - 代码架构说明

## 这个模块是干嘛的？

日历页面，可以：
- 查看每天的事件（预览模式）
- 编辑事件：点击打开编辑页，长按拖拽改时间（编辑模式）
- 切换查看范围：单日 / 3日 / 周视图
- 下拉切换 预览↔编辑 模式

## 事件是怎么显示到正确位置的？

### 问题：一个 9:30 的事件，应该放在屏幕的哪个位置？

### 答案：用数学算出来

```
事件开始时间: 9:30 = 9.5 小时
每小时的高度: 56 像素

所以事件的 Y 坐标 = 9.5 × 56 = 532 像素
```

### 代码在哪？

`CalendarLayout.swift` 里的 `yOffset()` 函数：

```
输入：事件时间范围、日期、每小时高度
输出：Y 坐标（距离顶部多少像素）
```

## 拖拽改时间是怎么实现的？

### 整体流程

```
第1步：用户长按事件块（0.3秒）
        ↓
第2步：手指移动，事件块跟着动
        ↓
第3步：手指松开
        ↓
第4步：计算手指移动了多少像素
        ↓
第5步：把像素转换成时间变化
        ↓
第6步：更新事件的开始/结束时间
        ↓
第7步：保存，界面自动刷新
```

### 详细过程

```
用户长按 EventBlock
    │
    │  （等待 0.3 秒）
    │
    ▼
手势识别器激活（LongPressDragGesture）
    │
    │  记住手指初始位置
    │
    ▼
用户拖动手指
    │
    │  计算：当前位置 - 初始位置 = 移动了多少
    │  事件块跟着移动（视觉效果）
    │
    ▼
用户松手
    │
    │  得到最终的移动距离（比如往下移动了 112 像素）
    │
    ▼
一层层往上传递这个数字
    │
    │  EventBlock
    │      ↓ "我被拖了 112 像素"
    │  TimelineDayView
    │      ↓ "某事件被拖了 112 像素"
    │  TimelineView
    │      ↓ 继续往上传
    │  TimelineContainerView
    │      ↓ 继续往上传
    │  CalendarPageView
    │
    ▼
CalendarPageView 处理这个信息
    │
    │  1. 这个事件原来在 Y=532 的位置
    │  2. 被拖了 112 像素，新位置 Y=644
    │  3. 644 像素 ÷ 56 像素/小时 = 11.5 小时 = 11:30
    │  4. 吸附到最近的 15 分钟 → 11:30
    │  5. 事件时长 1 小时不变
    │  6. 新时间：11:30 - 12:30
    │
    ▼
保存到 EventStore
    │
    ▼
界面自动刷新，事件显示在新位置
```

### 像素转时间的代码在哪？

`CalendarLayout.swift` 里的 `timeFromYOffset()` 函数：

```
输入：Y 坐标、日期、每小时高度
输出：对应的时间

特点：会自动吸附到 15 分钟的整数倍
      比如算出 11:23 → 自动变成 11:15 或 11:30
```

## 怎么切换 预览/编辑 模式？

### 操作方式
在顶部下拉，拉过一定距离后松手，就会切换模式

### 代码怎么判断？

```
用户滚动页面
    │
    ▼
系统告诉我们：滚动到了什么位置
    │
    │  scrollY = -80（负数表示往下拉）
    │
    ▼
CalendarPageStateMachine 判断
    │
    │  问：scrollY < -60 吗？（-60 是切换的阈值）
    │  答：是的，-80 < -60
    │
    │  问：上次切换后回到过顶部吗？
    │  答：是的
    │
    │  结论：切换模式！
    │
    ▼
更新状态：preview → edit（或反过来）
    │
    ▼
界面变化：
    - 网格线：虚线 ↔ 实线
    - 点击事件：无反应 ↔ 打开编辑
    - 长按事件：无反应 ↔ 可以拖拽
```

## 预览模式 vs 编辑模式 有什么区别？

| 功能 | 预览模式 | 编辑模式 |
|------|---------|---------|
| 网格线样式 | 虚线 | 实线 |
| 日期标签 | 不显示 | 显示 |
| 时间轴格式 | 简单 (0, 1, 2...) | 完整 (00:00, 01:00...) |
| 点击事件块 | 没反应 | 打开编辑页面 |
| 长按事件块 | 没反应 | 可以拖拽改时间 |

## 单日/3日/周 视图有什么区别？

| 视图 | 显示几天 | 怎么切换日期 | 事件块显示文字吗 |
|------|---------|-------------|----------------|
| 单日 | 1 天 | 左右滑动翻页 | 显示 |
| 3日 | 3 天 | 横向滚动 | 显示 |
| 周 | 7 天 | 横向滚动 | 不显示（太窄了） |

## 数据存在哪？

### EventStore（事件仓库）

```
作用：存储所有事件，提供增删改查

存储位置：手机本地（UserDefaults）

当事件变化时：
    EventStore 通知 → CalendarPageView 收到通知 → 重新计算 → 界面刷新
```

### CalendarViewState（日历状态）

```
存储内容：
    - selectedDayOffset：当前看的是哪一天（0=今天，1=明天，-1=昨天）
    - rangeMode：当前是日/3日/周视图
```

## 函数速查表

### CalendarLayout.swift（工具箱）

| 函数名 | 干嘛用的 |
|-------|---------|
| `yOffset()` | 告诉你：这个时间的事件，应该放在 Y 坐标多少的位置 |
| `eventHeight()` | 告诉你：这个事件有多长，应该画多高 |
| `timeFromYOffset()` | 告诉你：这个 Y 坐标对应几点几分 |
| `occurrencesForDate()` | 告诉你：这一天有哪些事件 |

### CalendarPageView.swift（主控制器）

| 函数名 | 干嘛用的 |
|-------|---------|
| `handleEventDrag()` | 处理拖拽：算出新时间，保存事件 |
| `handleScroll()` | 处理滚动：判断要不要切换模式 |
| `rebuildOccurrencesCache()` | 重新整理"每天有哪些事件"的清单 |

### EventBlock.swift（事件块）

| 组件名 | 干嘛用的 |
|-------|---------|
| `LongPressDragGesture` | 监听长按+拖动的手势 |

## 一图流：数据怎么流动的

```
┌─────────────┐
│ EventStore  │ ← 所有事件都存在这里
└──────┬──────┘
       │
       │ 事件列表
       ▼
┌──────────────────┐
│ CalendarPageView │ ← 拿到事件，整理成"每天的事件清单"
└──────┬───────────┘
       │
       │ 今天的事件清单
       ▼
┌──────────────────┐
│ TimelineDayView  │ ← 拿到清单，计算每个事件的位置
└──────┬───────────┘
       │
       │ 位置信息
       ▼
┌──────────────────┐
│ EventBlock       │ ← 在正确位置画出事件块
└──────────────────┘


用户拖拽时，信息反向流动：

┌──────────────────┐
│ EventBlock       │ ← 用户拖拽，得到"移动了多少像素"
└──────┬───────────┘
       │
       │ 移动距离
       ▼
┌──────────────────┐
│ CalendarPageView │ ← 把像素转成时间，算出新的开始/结束时间
└──────┬───────────┘
       │
       │ 更新事件
       ▼
┌─────────────┐
│ EventStore  │ ← 保存修改
└─────────────┘
       │
       │ 通知变化
       ▼
    界面自动刷新
```
